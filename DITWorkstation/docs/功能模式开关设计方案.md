# DIT 工作站功能模式与个人版设计方案

> 版本：v2.0（修订版）
> 适用代码库：`DIT_tools`（PySide6 + SQLite 桌面应用）
> 修订依据：现有代码核查、功能模式方案评审、独立个人版方案评审

## 一、结论摘要

当前最适合的实现路线是：

1. 一套代码、一个安装包；
2. 在 `settings.json` 的 `app_config` 段保存 `usage_mode`；
3. 启动时读取模式，构建个人版或团队版界面；
4. 个人模式只隐藏团队功能，不删除数据库数据；
5. 保存后重启生效，不在运行中动态重建主窗口。

该路线可行性较高，适合当前版本落地。预计工作量为 **6～9 人日**，原方案中的 4～6 人日偏乐观，原因是当前导航、视图栈、工作区选择器、备份目标和后台服务存在较强耦合。

如果未来需要独立的个人产品、独立安装包或不同授权模式，再在此基础上抽取 `core + editions/personal + editions/team` 的代码结构。独立个人版不应通过复制仓库后长期手工删除文件实现。

## 二、背景与目标

### 2.1 背景

DIT 工作站当前面向完整 DIT 团队工作流，包含：

- 工作区和项目两级结构；
- 媒体导入、备份、校验和验证；
- 场景、镜头、镜次拍摄日志；
- 素材评级、检索和信息维护；
- 备份方案模板、项目模板；
- 归档、恢复、报告生成；
- 操作审计日志；
- 相机卡自动识别与自动化导入/备份。

个人摄影师或独立创作者通常只需要：

- 项目管理；
- 媒体导入；
- 单目标备份和校验；
- RAW 提取；
- 文件重命名；
- 素材检索和信息维护。

团队功能如果全部展示，会增加工作区、日志、报告、模板和交接等概念负担。

### 2.2 目标

1. 默认团队模式，老用户升级后行为不变；
2. 个人模式隐藏团队向入口和组件；
3. 不删除数据库数据，不做数据库迁移；
4. 个人模式可完成“建项目 → 导入 → 单目标备份 → 检索 → 重命名”主流程；
5. 切回团队模式后，日志、评级、报告、模板、归档等功能恢复；
6. 个人模式和团队模式共享同一套数据库格式；
7. 为未来独立个人版保留清晰的代码拆分边界。

### 2.3 非目标

- 不做服务端或云端多用户协作；
- 不在 MVP 阶段实现任意粒度的用户自定义开关；
- 不在 MVP 阶段动态重建主窗口；
- 不删除团队业务服务和数据库表；
- 不直接复制整个代码库维护一个长期分叉版本；
- 不因为个人模式而迁移、重命名或删除已有项目数据。

## 三、现有代码约束

### 3.1 配置持久化

`AppConfig` 位于：

```text
DITWorkstation/DITWorkstation/App/__init__.py
```

配置持久化位于：

```text
DITWorkstation/DITWorkstation/Utils/common.py
```

实际结构是：

```json
{
  "app_config": {
    "usage_mode": "team"
  }
}
```

`save_app_settings()` 会合并写入 `app_config`，`apply_saved_config()` 会把已知字段恢复到 `AppConfig`。因此新增 `usage_mode` 不需要修改持久化框架。

### 3.2 导航与主窗口耦合

导航单一事实源位于：

```text
DITWorkstation/DITWorkstation/App/navigation.py
```

当前 `main_window.py` 中存在以下耦合：

- 导航列表直接遍历全量 `NAV_ITEMS`；
- 视图栈的 `addWidget` 顺序与 `NAV_ITEMS` 顺序一致；
- `Ctrl+1~9` 使用硬编码范围；
- F5 刷新通过 `NAV_ITEMS[index]` 找视图；
- 数据变更处理通过 `NAV_ITEMS[index]` 判断页面；
- `_running_workers()` 直接引用多个视图属性；
- `Ctrl+L`、备份完成跳日志、概览跳日志等入口依赖日志页存在。

因此不能只修改 `get_nav_index()`，必须统一引入“当前激活导航列表”。

### 3.3 工作区与项目选择器

当前 `WorkspaceProjectSelector`：

- 总是创建工作区下拉框；
- 项目列表会按当前工作区过滤；
- 新建项目时要求解析出一个工作区；
- 无工作区时会提示用户先创建工作区。

个人模式不能只隐藏工作区控件，否则项目列表和新建项目流程仍然不可用。需要增加个人模式行为：项目显示全部项目，新建项目传入 `workspace_id=None`，由数据库归入 `default` 工作区。

### 3.4 数据库默认工作区

`DatabaseService.create_project()` 已支持：

- `workspace_id=None` 时自动创建或使用 `default` 工作区；
- 旧项目迁移到 `default` 工作区；
- `default` 工作区不可删除。

个人模式不应强制把当前会话工作区设置为 `default`，否则属于其他工作区的已有项目可能被过滤而暂时不可见。个人模式项目选择器应显示全部项目，只有新建项目默认归入 `default`。

### 3.5 备份和相机卡自动化

当前备份视图的目标列表初始为空，首次备份必须点击“添加目标”。因此个人模式不能完全隐藏添加目标按钮，应保留添加第一个目标的能力，并在已有一个目标后禁用继续添加。

当前 `VolumeMonitor` 只负责检测存储卡，`CardAutomationService` 负责自动导入/备份。个人模式可以继续启动 `VolumeMonitor`，但必须禁止自动化流程启动。仅保留配置默认值为关闭是不够的，因为用户可能曾在团队模式开启该配置。

## 四、方案选型

### 4.1 路线 A：运行时功能模式（推荐）

在 `settings.json` 保存 `usage_mode`：

```python
class UsageMode(str, Enum):
    TEAM = "team"
    PERSONAL = "personal"
```

特点：

- 一套代码和一个安装包；
- 老用户默认团队模式；
- 个人模式仅做 UI 和交互裁剪；
- 数据库和服务层不变；
- 切换后重启生效；
- 适合当前版本快速落地。

### 4.2 路线 B：独立个人版

个人版有独立入口和独立构建配置，只导入个人功能模块。

特点：

- 个人版源码和界面更干净；
- 安装包可能更小；
- 可以独立授权和发布；
- 需要两套入口、构建、测试和发布流程；
- 仍必须保持数据库兼容；
- 不适合作为当前 MVP 的第一步。

### 4.3 路线 C：复制仓库后删除团队代码

不建议。短期看似简单，长期会产生：

- 修复和功能无法同步；
- 数据库迁移逻辑出现差异；
- 两套依赖和打包配置逐渐分叉；
- 无法确定哪些公共代码可以安全删除。

## 六、运行时功能模式设计

### 6.1 `App/feature_flags.py`

新增核心模块，职责包括：

- 读取并校验当前模式；
- 持久化模式；
- 返回激活导航项；
- 判断导航是否可见；
- 判断组件特性是否启用。

建议接口：

```python
def get_usage_mode() -> UsageMode:
    ...

def set_usage_mode(mode: UsageMode) -> None:
    ...

def is_personal_mode() -> bool:
    ...

def is_team_mode() -> bool:
    ...

def is_nav_enabled(key: str) -> bool:
    ...

def get_active_nav_items() -> list:
    ...

def is_enabled(feature: str) -> bool:
    ...
```

非法值和缺失值均回退到 `UsageMode.TEAM`。

模块依赖必须避免循环导入：`feature_flags.py` 可以导入 `NAV_ITEMS`；`navigation.py` 不应在模块顶层反向导入 `feature_flags.py`。如果 `get_nav_index()` 需要过滤，应使用局部导入或由 `feature_flags` 提供独立的查询函数。

### 6.2 主窗口构建策略

第一版不做视图懒加载。主窗口仍实例化全部视图，但只把激活视图加入导航和 `QStackedWidget`。

原因：当前关闭事件、后台 worker、数据总线和跨视图跳转直接引用多个视图属性。直接不实例化隐藏视图会扩大改动范围，并可能造成属性不存在或关闭流程遗漏后台任务。

主窗口新增：

```python
self.active_nav_items = get_active_nav_items()
self.view_by_key = {
    "dashboard": self.dashboard_view,
    "import": self.import_view,
    "backup": self.backup_view,
    "log": self.log_view,
    "raw": self.raw_view,
    "rename": self.rename_view,
    "search": self.search_view,
    "asset_info": self.asset_info_view,
    "report": self.report_view,
}
```

所有索引相关逻辑改用 `active_nav_items`：

- 导航列表；
- 视图栈；
- F5 刷新；
- `data_changed` 当前页面判断；
- `Ctrl+1~N`；
- `get_nav_index()`；
- 主窗口跳转。

所有跨视图跳转必须检查索引是否为 `None`，禁止直接把隐藏页面的 `None` 传给 `setCurrentRow()`。

### 6.3 快捷键

个人模式：

- 动态注册 `Ctrl+1~Ctrl+7`；
- 不注册 `Ctrl+L`；
- `Ctrl+F`、`Ctrl+I`、`Ctrl+B` 保留；
- F5 和 Esc 继续保留；
- 快捷键说明不应显示“Ctrl+L 跳拍摄日志”。

### 6.4 设置生效策略

模式在启动时确定。设置对话框中修改后：

1. 立即写入 `app_config.usage_mode`；
2. 提示“重启后生效”；
3. 提供立即重启或稍后重启；
4. 不尝试动态重建已存在的主窗口。

## 七、个人模式具体行为

### 7.1 项目选择器

修改 `WorkspaceProjectSelector`：

- 增加 `show_workspace` 或等效个人模式参数；
- 个人模式隐藏工作区标签、下拉、创建和编辑按钮；
- 项目查询使用全部工作区；
- 新建项目调用 `create_project(name=name, workspace_id=None)`；
- 删除项目行为按现有安全确认逻辑保留或另行评估；
- 不修改已有项目的 `workspace_id`。

### 7.2 首启向导

团队模式保持：

```text
欢迎 → 创建工作区 → 创建项目 → SOP 提示 → 完成
```

个人模式改为：

```text
欢迎 → 创建项目 → 完成
```

个人模式创建项目时由数据库自动准备 `default` 工作区。向导完成后仍设置当前项目并跳转媒体导入。

### 7.3 概览页

个人模式隐藏：

- 工作区操作；
- 拍摄日志统计卡或日志相关提示；
- 日志快捷按钮；
- 报告快捷按钮；
- 项目模板按钮；
- 归档和恢复按钮；
- 最近操作审计面板。

个人模式保留导入、备份、项目选择和核心进度提示。`_refresh()` 不应继续构造包含日志或报告的 SOP 文案。

### 7.4 媒体导入

隐藏“关联拍摄日志”选项，并将导入参数中的日志关联值固定为空。导入、校验和元数据读取逻辑保持不变。

### 7.5 数据备份

个人模式：

- 保留添加第一个备份目标的按钮；
- 已存在一个目标后禁用添加第二个目标；
- 隐藏清空多目标相关操作，或将其改为清空当前唯一目标；
- 隐藏备份方案模板控件；
- 保留算法和拷贝后验证设置；
- 隐藏 MHL 导出；
- 隐藏备份完成后的“去拍摄日志”按钮。

不能只隐藏“添加目标”，否则个人模式无法首次执行备份。

### 7.6 素材信息和素材检索

个人模式隐藏：

- 星级评级控件；
- 批量评级操作；
- 评级筛选；
- 拍摄日志筛选；
- 结果表中的评级和日志列，或改为明确的只读兼容列。

如果控件对象仍然创建但仅设置不可见，搜索过滤逻辑必须显式传入 `rating=None` 和 `log_id=None`，不能假定用户界面控件存在有效值。

### 7.7 存储卡功能

个人模式继续启动 `VolumeMonitor`，保留检测到存储卡后跳转导入的能力。

自动化启动条件必须同时满足：

```python
config.auto_card_automation_enabled and is_enabled("card_automation")
```

个人模式下即使配置文件中保存了团队模式开启过的自动化设置，也不得启动 `CardAutomationService`。

## 八、实施步骤

### 阶段 0：冻结产品语义

1. 明确模式是设备级配置；
2. 明确重启后生效；
3. 明确个人模式不迁移数据；
4. 明确个人模式项目查询显示全部项目；
5. 明确个人模式备份仍支持一个目标；
6. 明确团队服务和数据库表暂不删除。

### 阶段 1：开关底座

1. `AppConfig` 增加 `usage_mode="team"`；
2. 新建 `App/feature_flags.py`；
3. 实现模式校验、持久化、导航过滤和组件开关；
4. 修改 `get_nav_index()`；
5. 新增开关单元测试。

### 阶段 2：主窗口导航

1. 建立 `active_nav_items` 和 `view_by_key`；
2. 导航、视图栈和索引逻辑全部使用激活列表；
3. 修改 F5、数据变更、worker 检查和关闭流程；
4. 修改快捷键注册；
5. 修改所有跨视图跳转的 `None` 容错；
6. 增加两种模式下主窗口构建测试。

### 阶段 3：项目选择和首启向导

1. 为选择器增加个人模式布局；
2. 个人模式显示全部项目；
3. 个人模式创建项目时使用默认工作区兜底；
4. 调整首启向导页序；
5. 测试已有多工作区数据库在个人模式下项目仍可见。

### 阶段 4：设置入口

1. 设置对话框增加“使用场景”；
2. 保存到 `app_config.usage_mode`；
3. 显示重启提示；
4. 个人模式隐藏相机卡自动化配置；
5. 测试保存、回读和非法值回退。

### 阶段 5：视图裁剪

按以下顺序实施：

1. 概览页；
2. 备份页；
3. 项目选择相关视图；
4. 媒体导入页；
5. 素材信息页；
6. 素材检索页；
7. 设置和帮助菜单。

每修改一个视图，都同时补充团队模式回归和个人模式可见性测试。

### 阶段 6：回归和文档

1. 运行完整单元测试；
2. 运行 offscreen UI 测试；
3. 个人模式手动执行核心流程；
4. 切换回团队模式确认数据和功能恢复；
5. 更新 `README.md` 和用户手册；
6. 检查 Windows、macOS、Linux 的设置路径和打包启动行为。

## 九、测试方案

### 9.1 开关单元测试

- 缺少 `usage_mode` 时为团队模式；
- `usage_mode="foo"` 时回退团队模式；
- `set_usage_mode(PERSONAL)` 可保存到 `app_config`；
- `apply_saved_config()` 后仍能恢复个人模式；
- 团队模式激活 9 项导航；
- 个人模式激活 7 项导航，顺序正确；
- 个人模式下 `ratings`、`archive_restore`、`card_automation` 等为关闭；
- 团队模式下所有现有组件开关为开启。

### 9.2 UI 测试

- 两种模式的 `MainWindow` 均能构建；
- 导航数量和 `QStackedWidget` 数量一致；
- `Ctrl+数字` 不越界；
- F5 不访问隐藏页面；
- 概览、导入、备份的跨视图跳转不抛异常；
- 个人模式项目选择器不显示工作区操作；
- 个人模式可以创建项目；
- 个人模式备份可以添加一个目标；
- 个人模式搜索不会访问已隐藏的日志/评级控件。

### 9.3 数据兼容测试

- 无 `usage_mode` 的旧设置文件可以启动；
- 旧数据库可以在个人模式打开；
- 含日志、评级、报告数据的数据库不会被修改或删除；
- 个人模式新增项目可在团队模式看到；
- 团队模式已有项目在个人模式仍可查询；
- 个人模式切回团队模式后日志、评级、报告和模板数据仍存在。

### 9.4 手动冒烟流程

```text
个人模式
  → 首启创建项目
  → 媒体导入
  → 添加一个备份目标
  → 执行备份并验证
  → 素材检索
  → RAW 提取
  → 文件重命名

团队模式
  → 重启应用
  → 拍摄日志
  → 评级和评级筛选
  → 多目标备份
  → MHL 导出
  → 报告生成
  → 模板、归档和恢复
```

当前代码库不需要立即完成物理目录迁移。可以先通过两个入口和两个 spec 文件模拟该结构。

### 10.2 独立个人版原则

- 个人入口不导入日志、报告等团队视图；
- 个人构建配置不打包未引用的团队模块；
- 个人版不再需要运行时 `feature_flags`；
- 个人版仍保留数据库迁移和兼容代码；
- 个人版不能删除团队数据字段和表；
- 两个版本可以共享同一个数据库；
- 个人版和团队版必须分别测试同一数据库的读写兼容性。

### 10.3 独立个人版实施顺序

1. 先建立独立 `personal_main.py`；
2. 建立个人版导航清单；
3. 个人入口只导入 7 个个人视图；
4. 抽取共享配置、数据库、会话、worker 和通用控件；
5. 重写个人版项目选择器；
6. 将备份页限制为单目标；
7. 移除个人版设置中的团队配置项；
8. 增加 `DITWorkstation-personal.spec`；
9. 确认 PyInstaller 不会通过动态导入带入团队模块；
10. 运行个人版和团队版共享数据库兼容测试；
11. 最后再删除确定没有引用的团队模块。

## 十一、风险与控制措施

| 风险 | 影响 | 控制措施 |
|------|------|----------|
| 导航索引漂移 | 跳错页面或越界 | 所有索引基于 `active_nav_items` |
| 隐藏视图属性不存在 | F5、关闭、worker 检查崩溃 | MVP 仍实例化全部视图 |
| 工作区被强制设为 default | 旧项目暂时不可见 | 个人模式显示全部项目，不设置当前工作区 |
| 备份无法添加首个目标 | 个人核心流程中断 | 保留添加首目标，限制第二目标 |
| 团队自动化配置残留 | 个人模式误启动自动化 | 启动条件同时检查 feature flag |
| 隐藏控件仍被逻辑访问 | 搜索或刷新抛异常 | 保留对象或增加模式分支，并补 UI 测试 |
| 设置修改后界面状态混乱 | 用户误以为已生效 | 明确重启生效并提供重启入口 |
| 独立个人版代码分叉 | 长期维护成本上升 | 先抽取公共核心，再拆入口和构建配置 |
| 删除团队表或字段 | 切回团队版数据损坏 | 个人模式和个人版均保留数据库兼容层 |

## 十三、验收标准

### 团队模式

- 未配置 `usage_mode` 时启动行为与当前版本一致；
- 导航保持 9 项；
- 现有测试全部通过；
- 日志、评级、报告、模板、归档、多目标备份、MHL 和相机卡自动化行为不回归。

### 个人模式

- 导航只有 7 项；
- 工作区操作不显示，但所有项目仍可查询；
- 可以直接创建项目；
- 可以导入素材；
- 可以添加并执行单目标备份；
- 可以检索、提取 RAW、重命名和查看素材信息；
- 不显示日志、报告、模板、归档、审计和 SOP 团队入口；
- 不启动相机卡自动化；
- 不删除任何数据库数据。

### 模式切换

- 设置写入 `settings.json` 的 `app_config.usage_mode`；
- 重启后模式正确恢复；
- 团队模式和个人模式之间切换不改变项目、素材和历史数据；
- 个人模式新增的数据可以被团队模式读取。
