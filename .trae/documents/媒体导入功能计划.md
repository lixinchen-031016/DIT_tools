# 媒体导入功能实现计划

## 一、需求分析

### 1.1 功能目标
添加导入图片/视频进入项目的功能，核心原则：
- **原文件位置不动**：导入时只在数据库中记录引用，不移动/复制原文件
- **修改时才复制**：如需重命名等修改操作，先复制一份到项目工作目录再进行修改

### 1.2 现有代码基础
- 已有 `MediaAsset` 数据模型（[Models/__init__.py](file:///Users/lixinchen/PycharmProjects/DIT_tools/DITWorkstation/DITWorkstation/Models/__init__.py#L151-L170)）
- 已有 `DatabaseService` 素材资产管理（[database_service.py](file:///Users/lixinchen/PycharmProjects/DIT_tools/DITWorkstation/DITWorkstation/Services/database_service.py#L266-L386)）
- 已有项目管理（左侧项目列表）在拍摄日志视图中
- 已有素材检索页面 `SearchView`
- 支持的图片格式：`.jpg .jpeg .png .tiff .tif`
- 支持的RAW格式：`.cr2 .cr3 .nef .arw .dng .orf .rw2 .raf .pef .srw`

### 1.3 缺少的能力
- 视频格式支持
- 专门的导入服务层（MediaImportService）
- 导入视图界面
- 项目工作目录概念（用于存放修改后的副本）

## 四、关键设计决策

### 4.1 导入模式设计
- **引用模式（默认）**：仅在数据库中登记，原文件位置不动。`file_path` 指向原始路径，`is_working_copy = False`
- **复制模式**：将文件复制到项目工作区后再登记。`file_path` 指向工作区副本，`original_path` 记录原始路径，`is_working_copy = True`

### 4.2 项目工作目录结构
```
项目工作区/ (base_path 或 项目名_DIT_Workspace)
├── originals/       # 可选：原始文件副本（如选择复制模式）
├── exports/         # 导出文件
└── temp/            # 临时文件
```

### 4.3 去重策略
- 优先按 `文件路径 + 项目ID` 查重（快速）
- 如果路径不同，再按 `校验和 + 项目ID` 查重（准确但慢）
- 导入时用户可选择跳过重复或强制重新导入

## 五、潜在风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| 大量文件导入时UI卡顿 | 用户体验差 | 使用后台线程 + 进度回调，分批处理 |
| 视频元数据读取依赖外部库 | 功能不可用 | 先实现基础信息（大小、扩展名），后续可选集成 ffprobe |
| 跨平台路径一致性 | Windows/macOS路径问题 | 统一使用 pathlib，存储绝对路径 |
| 原文件被移动/删除后断链 | 素材失效 | 导入时计算校验和，提供"重新定位文件"功能 |
| 数据库中重复数据 | 数据混乱 | 路径+项目ID建唯一索引，导入前严格查重 |
